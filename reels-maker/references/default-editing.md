# 새 브이로그의 기본 편집

먼저 [형식 선택](formats.md)을 따른다. 아래 역할별 연출은 별도 스타일 요청이 없는 **이야기형 릴스**의 제안·그림 콘티·영상 시안에 적용한다. 타임로그는 담백한 시간·행동 자막, 일상 모음은 가벼운 감상·관찰 자막을 중심으로 하며 강한 팝·글로우를 자동 적용하지 않는다. 이번 요청 > 승인한 개인 지침 > 이 기본값 순이다. 기존 작품을 자동 재제작하거나 개인 프로필을 변경하지 않는다. 형식 선택과 선택적 레퍼런스 링크 입력 뒤 컷당 최대 길이 질문(기본 제안 2초), 그림 콘티와 사용자 확인 과정을 따른다. 시간 표시 여부 질문은 타임로그에만 적용하며 이야기형에는 하지 않는다. 다른 형식에서도 사용자가 직접 요청한 시간 설정은 보존한다. 이번 검증 영상의 6컷·3초·제목·문구·촬영시각을 공통 기본값으로 복사하지 않는다.

## 자막 역할

| 역할 | 실제 번들 폰트 | 1080×1920 시작값 | 연출 |
|---|---|---|---|
| 상황·행동·연결 | Pretendard SemiBold | 70px, 흰색, 얇은 어두운 테두리 1px와 그림자 | 짧은 한 의미. 장면을 설명하거나 다음 행동으로 연결 |
| 반응·절정 | 마루 부리 SemiBold | 94px, 연노랑 `#FFF18C`, 어두운 외곽선 최대 5px | 기울임과 짧은 팝. 웃음·놀람·핵심 동작에 집중 |
| 첫 장면의 제목 | 마루 부리 SemiBold | 104px 전후, 밝은 분홍·흰색과 분홍 글로우 | 첫 영상 위 약 1~1.6초. 별도 인트로로 원본을 늘리지 않음 |
| 마무리 | 마루 부리 SemiBold | 76px, 부드러운 분홍빛 글로우 | 마지막 표정·동작과 원음을 남기고 작은 반짝임 |
| 선택한 촬영시간 | SUIT SemiBold | 42px, 흰색과 어두운 테두리 2px | 작은 보조 정보. 위치 지시가 없으면 위쪽 왼편에 고정 |

수치는 검증한 출발점이며 고정된 모든 컷의 좌표나 크기가 아니다. 글자 폭·휴대폰 크기·얼굴과 손을 보고 조정한다. 시간은 사용자가 켰고 메타데이터가 확인된 컷에만 쓴다. 사용자가 정한 중앙 시간·다른 폰트·차분한 분위기를 우선한다. 제목은 소재에 맞게 정하고, 의미가 없으면 억지로 추가하지 않는다. 첫 컷 제목과 본문은 순서대로 보여줘 동시에 몰리지 않게 한다.

폰트는 `assets/fonts/Pretendard-SemiBold.otf`, `MaruBuri-SemiBold.ttf`, `SUIT-SemiBold.ttf`를 스킬 기준으로 해석한다. 역할별 계획에 실제 경로·굵기·색·위치를 명시한다. 정적 폰트에 이전 가변 `font_weight`를 남기지 않는다. 기울임은 실제 글자 변형이며 이름에 Italic만 붙여 적용했다고 하지 않는다. 레퍼런스 제작자가 쓴 정확한 폰트명을 확인한 것은 아니다. 실제 적용할 폰트는 그림 생성의 글자 모양과 구분해 기록한다.

## 문장과 리듬

이야기형은 자막 스타일을 적용하기 전에 [이야기와 자막](narrative.md)에서 사용자 맥락·이야기 한 줄·장면 역할을 정한다. 타임로그와 일상 모음의 자막 밀도·강조는 [형식별 기준](formats.md)을 따른다. 이 문서의 본문/반응은 시각적 역할이며 이야기의 도입·변화·회수를 자동으로 만드는 기능이 아니다. 이야기형에서는 전체를 잇는 관점과 문장을 먼저 설계한다.

- 본문으로 맥락을 이어가다가 반응이 있는 순간에 노란 기울임으로 전환한다. 장소·물건 이름을 매 컷 나열하기보다 확인한 상황과 감정을 짧게 담는다. 원본에 없는 행동·대사·관계를 만들어 넣지 않는다.
- 본문·리액션·타이틀의 색과 형태는 역할별로 유지한다. 컷마다 본문 전체를 노랑·민트·분홍으로 순환시키지 않는다. 강한 외곽선은 리액션에 집중하고, 제목의 글로우로 글자 획이 뭉개지지 않게 한다.
- 기본은 자연스러운 컷 연결이다. 실제 반응에 짧은 팝·버스트, 제목·마무리에 작은 반짝임을 사용한다. 장면이나 날짜가 바뀔 때 짧은 디졸브 등을 고르고, 모든 경계에 서로 다른 전환을 넣지 않는다. 강한 효과를 요구한 경우 그 요청을 우선한다.
- 본문 등장 약 0.12~0.18초의 페이드·작은 이동, 리액션 약 0.2초의 짧은 확대를 시작점으로 삼을 수 있다. 효과를 넣으려고 원본을 반복·정지하거나 승인한 최대 길이를 넘기지 않는다.

## 원음과 출력

최종 영상은 원본 선택 구간의 소리를 유지한다. BGM이 없다는 이유로 무음으로 만들지 않는다. 별도 요청이 없으면 배경 음악·효과음을 자동으로 내려받거나 추가하지 않는다. 사용자가 무음이나 다른 믹스를 요청하면 그 선택을 따른다. 원본에 오디오가 없는 구간은 그대로 무음이며 소리를 만들어 채우지 않는다.

영상의 밝기·색감도 원본 느낌을 유지하는 것이 기본이다. 사용자가 요청하지 않은 노출·감마·채도·화이트밸런스 보정을 자동으로 넣지 않는다. 자막의 글로우와 영상 전체의 밝기 보정은 구분한다.

HDR→SDR 변환은 화면의 밝기 범위를 실제로 바꾸는 처리다. HDR 태그나 파일 확장자만 보고 모든 입력에 같은 톤매핑·피크 밝기 값을 적용하지 않는다. 전송·재인코딩된 파일은 태그와 실제 표시 특성이 일치하지 않을 수 있으므로 기존 변환 여부도 확인한다. SDR 입력에는 HDR 톤매핑을 넣지 않고, 이미 확인한 변환 사본을 다시 톤매핑하지 않는다. 태그를 삭제하거나 감마를 임의로 낮추는 것을 일반적인 해결책으로 쓰지 않는다.

색상 변환이 필요하면 본편 합성 전에 대표 구간으로 원본·변환 사본·출력의 같은 장면을 비교한다. HDR 원본은 색 관리가 적용된 재생을 기준으로 삼고, HDR 표시 변환이 없는 단순 프레임 추출 이미지를 원본의 정확한 화면 밝기라고 간주하지 않는다. 피부·흰 옷·벽·어두운 원단의 밝기와 색, 밝은 부분의 디테일을 보고 변환을 고른다. 메타데이터 일치나 전체 평균 픽셀값만으로 원본 느낌 보존을 통과시키지 않는다. 기준 재생을 확인할 수 없으면 그 한계를 기록하고, 관측한 밝기·색 차이를 검수 완료로 덮지 않는다. 비교용 짧은 사본 준비는 제작 범위에서 진행하며 매번 새 승인 단계로 만들지 않는다.

HEVC/HDR·회전 원본은 보존하고 필요하면 작업 복사본을 만든다. 영상만 있는 작업 복사본을 써도 원음은 원본의 **같은 시작 구간·같은 길이**에서 가져와 최종 합성한다. 1080×1920, 24fps, H.264 SDR MP4를 기준으로 한다. 직접 RGB 프레임을 합성할 때는 RGB→YUV의 BT.709 변환과 limited 범위, BT.709 primaries/transfer/matrix를 명시하고 최종 파일에서 확인한다. 태그만 붙이는 것으로 실제 색변환을 대신하지 않는다. 오디오는 원음 크기를 유지하고 필요한 경계의 짧은 클릭 방지 페이드만 적용한다.

## 구현 범위와 검수

이 문서는 에이전트가 적용하는 편집 지침이며 실행 가능한 JSON 프리셋이나 새 render 옵션이 아니다. 기존 `scripts/render.py`는 무음 H.264 SDR 입력과 정적 한 줄 요소를 지원한다. 기울임·글로우·등장 애니메이션·다중 줄 제목·전환·원음 합성을 자동 제공한다고 설명하지 않는다.

지원되지 않는 연출은 작업 폴더에서 Pillow/PyAV/FFmpeg로 별도 합성하고 실제 산출물로 검증한다. 이번 요청이나 승인된 콘티 범위의 합성을 위해 같은 승인을 반복하지 않는다. 원음 유지 방침은 그대로 따르며, 해당 환경에서 합성할 수 없으면 미완료 항목과 대안을 설명한다. 조용히 원음을 지우거나 효과 없는 결과를 구현 완료라고 보고하지 않는다. 외부 유료 편집 서비스·폰트·음원을 임의 추가하지 않는다.

검수는 실제 폰트·배치, 출력 전체 디코드·프레임 수·해상도·색정보, 각 소스의 선택 구간과 최종 오디오, 대표 컷·등장/퇴장·씬 경계, 원본 해시 보존을 포함한다. 1080px 원본과 약 360px 너비에서 글자가 읽히는지, 얼굴·손·중요 행동을 가리지 않는지 확인한다. 공유 렌더 잠금이 지정된 환경에서는 별도 합성도 같은 잠금을 쓰고 잠금 파일 내용·소유권을 바꾸지 않는다. 직접 연속 재생·청취와 자동 수치/샘플 이미지 검수는 구분해 기록한다.
