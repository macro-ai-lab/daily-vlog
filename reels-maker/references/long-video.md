# 긴 영상과 큰 원본

## 첨부 용량을 넘는 경우

작은 파일은 대화 첨부로 받는다. 큰 파일은 편집을 실행하는 컴퓨터의 개별 파일 경로나 사용자가 지정한 폴더로 받는다. 경로 입력은 원본을 채팅 첨부로 다시 전송하는 과정이 없으며 앱의 첨부 크기 제한과는 별개다. 다만 디스크 여유 공간과 읽기 권한은 필요하다. 에이전트가 프레임을 확인하는 서비스의 처리는 기존과 같다.

휴대폰에만 있는 원본은 편집 컴퓨터로 전달하는 과정이 필요하다. 원격 Mac이라면 사용자의 손에 있는 아이폰에 접근 가능하다고 가정하지 않는다. 같은 기기의 경로처럼 보이더라도 로컬 Mac/원격 Mac을 구분한다. 전체 사진첩 권한을 요구하거나 다른 파일을 수집하지 않는다. 공유 링크 다운로드·사진첩 연동은 이 버전의 기능이 아니다. 사용자가 지정한 원본이 컴퓨터에 도착했는지 확인하고 분석한다. 아이폰 HEVC/HDR·회전·원음 지원은 긴 영상 분석 기능과 별개로 판단한다.

## 원본 전체에서 구간 찾기

짧은 영상에 쓰던 10%/50%/90%의 세 장만으로 긴 영상의 장면을 선택하지 않는다. 먼저 `inspect --files FILE`로 메타데이터와 편집 지원 여부를 확인한다. 영상의 시작·중간·끝을 포함하는 간격 샘플을 만든다:

```sh
bash scripts/run.sh survey FILE --output-dir WORKDIR/survey-v001
```

기본은 30초 이하의 간격으로 최대 60장이다. 상한에 걸리면 전체 범위를 유지하면서 간격을 늘린다. `survey.json`의 actual_interval_seconds를 보고 촘촘하게 확인할 범위를 정한다. 생성된 contact-*.jpg와 개별 프레임을 실제로 읽어야 한다. 도구는 장면의 의미·흔들림·인물을 자동 판정하지 않는다.

관심 구간을 예컨대 2분~2분20초로 좁힌 뒤 다시 확인한다:

```sh
bash scripts/run.sh survey FILE --start 120 --end 140 --interval 1 --max-frames 30 --output-dir WORKDIR/detail-v001
```

단일 분석은 최대 120장, 이미지는 긴 변 640px 이하이며 20장씩 묶는다. 원본을 전체 길이의 편집 사본으로 변환하거나 여러 영상 조각으로 미리 복사할 필요가 없다. 분석 이미지와 위치 기록만 생성한다. 끝 위치는 영상 끝보다 약간 앞에서 샘플링한다. 위치 기록은 추출을 요청한 원본 시각이며 프레임 단위의 정밀한 컷 지점 검증을 대신하지 않는다. 불완전한 분석은 survey.json의 status=incomplete로 남으며 완료로 제시하지 않는다.

원음이나 HEVC 등으로 inspect가 편집 불가라고 알려도 디코더가 읽을 수 있는 프레임은 분석에 이용할 수 있다. 이것이 해당 파일의 최종 렌더 지원이나 HDR 색상·방향의 정확한 표시를 보증하지 않는다. 분석 도중 파일 오류가 나면 해당 한계를 설명한다. 원본 변환·원음 처리는 기존 워크플로에서 필요한 선택을 받는다.

## 콘티와 잘라 쓰기

확인한 후보마다 원본 파일과 시작/끝 위치를 기록하고 장면 설명·선택 이유를 붙인다. 시각은 영상 안 위치이며 촬영시각이 아니다. “02:14~02:17 — 컵 내려놓는 동작”처럼 제안한다. 샘플 사이의 짧은 행동은 놓칠 수 있으므로 전체 행동을 다 찾았다고 하지 않는다. 후보 컷의 앞·중간·끝과 실제 크롭을 더 확인하고, 시각 분석으로 소리나 전체 움직임을 검수했다고 하지 않는다.

사용자가 콘티와 스타일을 정하면 기존 계획의 `source`, `start`, `duration`에 원본과 구간을 직접 넣는다. 같은 긴 원본을 여러 컷에서 써도 된다. 렌더러가 선택 구간을 읽으므로 긴 원본 전체를 줄여 붙이지 않는다. 기존 결과 길이(10~40초)와 컷 길이(0.5~4초)는 그대로다. 긴 입력 지원과 긴 완성본 지원을 혼동하지 않는다.
