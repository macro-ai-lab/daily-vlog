# 게시 전 검사

## 코드와 동기화

등록 목록 projects.json과 distribution.json을 확인한다. 공통 설치 정책 변경은 모든 등록 프로젝트에서 같은 템플릿·이 스킬을 동기화하고 `distribute.py check --repo ... --repo ... --require-all`을 통과한다. 누락을 “둘 다 적용”이라고 보고하지 않는다. 개별 제품의 변경이라면 해당 범위만 검증한다. 새로운 프로젝트는 설치 계약, 제품 도구·런타임, 공식 출처·고정 해시를 정하고 init 후 registry에 추가한다.

Git diff에서 제품 SKILL.md·기본값·개인 지침이 설치 작업 때문에 바뀌지 않았는지 확인한다. 셸/PowerShell 구문, Windows UTF-8 BOM/CRLF와 Mac LF/실행 권한, 동일 재실행·수정본/추가 파일/개인 지침·기록·잠금·링크/정션 보호를 검사한다. HTTPS·해시 회귀를 유지한다.

## 실제 배포물

`distribute.py package --repo REPO --output NEW_ZIP`으로 만든다. 허용 파일 목록을 쓰고 .git·인증·개인 자료·도구 캐시를 제외한다. archive/source 파일 목록·내용·실행 비트를 검사한다. 이미 검사한 ZIP에 다른 파일을 덮어쓰지 않는다.

각 제품의 최종 ZIP으로 네 경우를 실제 OS에서 검사한다. `smoke_matrix.py`는 새 프로젝트와 빈 캐시, 사용자 범위 설치, 동일 재실행, 새 프로세스, 수정본·개인 지침 보존을 검사한다. 기존 런타임 재사용과 첫 다운로드를 구분한다. 사용자 범위는 격리 캐시를 명시적으로 재사용할 수 있지만 보고한다. 런타임 없는 제품은 UI 도구 가용성과 파일 설치를 구분하고 설치 점검만을 위해 로그인·사진 업로드·게시하지 않는다.

CI의 네 경우는 OS/클라이언트 설치 경로 시험이다. 실제 Codex·Claude Code 계정의 프런트엔드 호출, 이미지 직접 열람, 새 채팅, 다른 계정 접근을 시험한 것이 아니다. 사용자 실기 보고, 직접 수행한 시험, 제어된 모의 검사와 미실행을 구분한다. 실행 가능한 경우 실제 세션에서 이미지 열람 후 간단한 명령이 계속 되는지 확인한다.

## GitHub 게시

사용자 승인 범위에서 main/브랜치 커밋과 push를 진행하고 GitHub Installation matrix 결과를 확인한다. 실패하면 원인을 고쳐 같은 검사를 다시 수행한다. 실행할 수 없는 환경을 성공으로 기록하지 않는다. README·버전·태그·릴리스 target의 전체 커밋 SHA·ZIP 이름을 맞춘다. 릴리스 설명은 실제 변경과 검증·한계만 쓴다. gh는 notes/body 파일로 실제 줄바꿈을 보존한다.

검사한 그 ZIP을 릴리스에 올리고 공개 URL로 다시 내려받아 SHA256을 비교한다. GitHub 소스와 ZIP의 루트 파일도 일치해야 한다. 설치 링크와 ZIP 링크가 이전 버전을 가리키지 않는지 확인한다. 최종 보고에는 적용된 프로젝트·릴리스·주요 변경·검증·남은 한계를 간단히 남긴다. 로컬 수정·커밋·파일 복사만으로 공개 반영 완료라 하지 않는다.
