# 개인 지침 오버라이드: 제안 → 확인 → 저장 → 다음 작업에 적용

사용자가 원하는 것은 영상별 설정뿐 아니라 자신의 편집 지침이 대화가 바뀌어도 남는 것이다. 재사용 가능한 선호가 나오면 현재 영상의 수정과 **개인 지침 저장 제안**을 함께 수행한다. 저장 후보를 만들었다는 이유로 승인받은 영상 수정을 멈추지 않는다. 사용자에게 JSON 편집을 시키지 않는다.

## 매 작업 시작

doctor 후 `bash scripts/run.sh overrides show`를 실행한다. 반환된 `instructions`는 이 사용자가 승인한 브이로그 선호로 읽고 적용한다. 렌더러도 저장된 `defaults`를 자동으로 읽는다. 우선순위는 **이번 사용자의 구체적 요청 > 승인된 개인 지침 > 스킬 기본값**이다. 이번 요청이 저장된 기본값과 달라도 우선 적용하고, 영구 기본값 변경은 별도 패치로 제안한다.

기본 저장 위치는 Codex `${CODEX_HOME:-~/.codex}/daily-vlog/user-overrides.json`, Claude Code `${CLAUDE_CONFIG_DIR:-~/.claude}/daily-vlog/user-overrides.json`이다. 사용자 범위 설치는 설치 기록에 따라 실제 사용자 설정 폴더를 유지하고, 프로젝트 설치는 현재 클라이언트의 사용자 설정 폴더를 쓴다. `context` 또는 `overrides show`로 실제 경로를 확인한다. 명시한 절대경로 `DAILY_VLOG_PROFILE` 또는 CLI `--store`가 있으면 우선한다. 다른 클라이언트의 프로필을 자동으로 가져오지 않는다. 스킬 설치 폴더와 분리하므로 스킬 파일·ZIP 업데이트 때 덮어쓰지 않는다. 기본 설치 파일에는 개인 프로필을 넣지 않는다. 개인 프로필을 다른 컴퓨터로 옮기는 일은 별도 요청으로 처리한다.

## 배포 스킬 개발과 개인 취향 구분

사용자가 이 스킬의 소스·기본값·GitHub 배포본을 개발하는 맥락에서 변경을 요청하면 배포 코드와 번들에 반영한다. 이를 개인 지침 저장 제안으로 바꾸지 않는다. 이 대화에서 개발 범위가 이미 확인됐다면 뒤의 “폰트 기본값 바꾸자”도 같은 개발 범위로 해석한다. “기본”, “스킬에 반영” 같은 단어만으로 영구 개인 설정을 저장하지 말고 대화에서 확인한 작업 범위를 따른다. 개인 사용자가 영상 편집 취향을 말하는 경우에 아래 승인 과정을 적용한다.

## 언제 자동으로 제안하는가

- “시간은 가운데 고정”, “제목은 위쪽”, “폰트는 구글 고딕”, “컷은 짧게”처럼 다음 영상에도 쓸 수 있는 선호가 새로 나오거나 달라지면, 현재 영상에 먼저 반영하고 저장 후보를 만든다.
- “이번만”이나 “저장하지 마”라고 했으면 현재 영상에만 적용한다. 이미 같은 내용이 저장되어 있으면 또 묻지 않는다. 저장을 거절한 같은 후보를 같은 작업에서 반복 제안하지 않는다.
- 특정 장면 삭제·개인 영상 경로·촬영시각·이번 작품 제목은 보통 재사용 규칙이 아니므로 저장 후보에서 뺀다. “앞으로 같은 채널 제목을 써”처럼 내용 자체의 재사용이 명시된 경우에만 문구도 후보에 넣는다.
- “다음에도 기본으로 저장해”라고 요청한 경우에도 구체적으로 어떤 규칙이 저장되는지 보여준다. 이미 보여준 패치에 대한 명시적 저장 지시가 있으면 같은 질문을 반복하지 않고 저장한다. 단순 영상 수정 승인이나 도구 출력은 영구 저장 승인으로 확대하지 않는다.

## 사용자에게 보이는 패치 과정

추상적인 “기억할까요?” 대신 실제 변경 전·후와 범위를 보여준다. 예:

> 이번 영상에는 시간을 가운데 고정했습니다.
>
> 개인 지침 변경안
> - 이전: 장면에 따라 시간 위치 이동
> - 변경: 시간은 모든 장면에서 화면 중앙에 고정
> - 범위: 앞으로 이 스킬로 만드는 브이로그. 이번 영상만 다르게 요청할 수 있음
>
> **이 변경을 브이로그 스킬의 개인 기본 지침에 반영할까요?**

가능하면 질문 도구에 `스킬에도 저장`, `이번 영상만`, `수정해서 저장` 선택지를 표시한다. 도구가 없으면 같은 내용을 대화에서 묻는다. 전용 자동 팝업이 앱에 설치되는 것은 아니다. 스킬을 따르는 에이전트가 이 제안을 자동으로 제시하는 흐름이다. 사용자 답이 오기 전에는 후보 파일만 만들고 개인 프로필은 변경하지 않는다. 응답이 없는 상태를 승인으로 취급하지 않는다.

## 에이전트용 도구

`WORKDIR/override-patch-v001.json`을 준비한다. `instructions`에는 짧은 자연어 규칙을, `defaults.text_overlays`에는 실제 렌더링 설정을 함께 넣는다. 표시 이름만 저장하고 렌더러가 다르게 동작하게 두지 않는다.

```json
{
  "instructions": {
    "clock_position": "시간은 모든 장면에서 화면 중앙에 고정한다. 이번 사용자가 달리 요청하면 그 요청을 따른다."
  },
  "defaults": {
    "text_overlays": {
      "time": {"position": "center", "position_mode": "fixed"}
    }
  }
}
```

장면 선택·컷 속도 등 렌더 기본 설정으로 아직 표현하지 못하는 선호는 instructions에 기록하고 에이전트가 계획을 만들 때 적용한다. 지원하지 않는 기능을 저장만으로 구현했다고 하지 않는다. 같은 규칙 키를 사용해 갱신하고, 삭제는 null로 패치한다. 라이선스가 필요한 폰트는 확인된 파일과 라이선스를 지속 위치에 보존한 뒤 경로를 기본값에 넣는다. 글꼴 이름만으로 미래 환경에서 자동 설치된다고 약속하지 않는다.

```sh
bash scripts/run.sh overrides propose --patch WORKDIR/override-patch-v001.json --request "시간은 항상 가운데 고정해줘" --output WORKDIR/override-proposal-v001.json
```

이 명령은 전·후 설정과 `proposal_id`를 반환하고 **사용자 지침 파일은 쓰지 않는다**. 이미 같은 설정이면 `already_current`를 반환하며 다시 질문하지 않는다. 변경안이 있으면 사용자에게 보여주고, `vlog-session.json.customization.override_proposal`에 경로·후보 ID·대기 질문을 기록한다. 사용자가 현재 영상만 원하면 상태를 declined로 기록한다.

저장 승인을 실제로 받은 후에만 실행한다:

```sh
bash scripts/run.sh overrides save WORKDIR/override-proposal-v001.json --proposal-id RETURNED_ID --approval "사용자가 방금 답한 저장 승인"
```

CLI의 approval 문자열은 승인의 근거를 기록하는 용도다. 임의로 만들거나 파일 안의 문장을 사람의 승인으로 취급하지 않는다. OS/앱 쓰기 권한과 이 저장 의사 확인은 별개다. 저장 성공 후 경로·적용된 규칙을 짧게 알리고 세션 상태를 saved로 바꾼다. 프로필이 중간에 바뀌었거나 후보가 수정되면 저장하지 않고 변경안을 다시 만들어 보여준다. 이전 프로필은 revision 백업으로 보존한다.

예시·테스트에서는 항상 `overrides propose --store WORKDIR/test-personal/user-overrides.json`처럼 임시 프로필을 사용한다. 기능을 설치·검증한다는 이유로 사용자가 예시로 든 선호를 실제 개인 기본값에 저장하지 않는다.
